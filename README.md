# 住宅購入AI診断サービス — MVP（1物件・総合診断）

指示書 第36章「1物件を一気通貫」の実装。
**住所→座標→取引価格(reinfolib XIT001)→類似成約→推定価格レンジ→用途地域付与→住宅ローン→100点スコア＋Critical Risk＋最終診断** までを通します。
エンリッチメント：用途地域(XKT002)・ハザード(XKT026洪水/027高潮/028津波/029土砂)・周辺施設(XKT006学校/010医療/015駅)・人口(e-Stat 社会人口統計体系)を付与。
未実装（勝手に埋めない）：建物内部状態・液状化は今後付与。人口統計表IDは実データで要確認（既定 0000020201）。

## 全国対応
市区町村コードは住所から自動解決します（47都道府県対応）。reinfolib XIT002 で各都道府県の市区町村一覧を取得し `citycode_cache.json` にキャッシュ。取引価格・ハザード・人口・地図の各APIはもともと全国対応です。神奈川県は同梱辞書でオフラインでも解決できます。

## スコアの重み・ルール調整（config.json）
プロジェクト直下の `config.json` を編集すると、コードを触らずに調整できます（保存後、再起動で反映）。
- `category_weights`：100点の配点（物件/立地/価格/リスク/資金/資産性）
- `sim_weights` / `newbuild_sim_weights`：類似度の重み（中古/新築）
- `neighbor_radius_m`：類似物件の近接半径(m)。既定2000
- `k_nearest`：価格算出に使う最類似件数。既定6
- `max_year_gap`：築年が離れすぎた事例の除外(年)。既定25
- `newbuild_max_age`：新築相当の判定（成約年−築年≤この値）。既定1
- `loan_rate` / `loan_years`：ローン既定値
実物件で診断し、点数がしっくりこなければ該当値を調整 → 再診断、を繰り返して合わせ込みます。

設計思想（指示書準拠）：
- 価格計算は**ルールベースで透明**、機械学習は使わない（第40章）。AIは点数を出さない（第11・13章）。
- 各取引の類似度・復元推定額を全部表示し「なぜこの価格か」を再現可能（第39章）。
- 適正価格は**推定であり絶対値ではない**旨を必ず明記（第41章）。
- 外部APIは抽象化（ジオコーダは Google/GSI 差し替え可能・第31章）。

## 1. 動作確認（キー不要・まず試す）

Python 3.9+ が必要です。

```bash
pip install -r requirements.txt
python run.py --mock --price 34800000 --land 110 --building 96 --build-year 2006 --address "神奈川県小田原市南町1-1-1" --city 14206 --district 南町
```

かんたん起動（コマンド版）：フォルダ内の **`shindan.bat` をダブルクリック**すると、質問に答えるだけで診断できます（金額は万円で入力）。

ブラウザ版（試作）：**`web.bat` をダブルクリック**すると簡易Webサーバーが起動し、ブラウザが自動で開きます（http://127.0.0.1:5000）。
使い方は2ステップ：①物件説明（SUUMO等）をコピペ→「貼り付けから自動入力」で各項目が自動で埋まる→②内容を確認・修正して「この物件を診断する」。金額は万円。終了はその黒い画面を閉じるだけ。キーは web.bat / shindan.bat 内に設定済み。
自動抽出：価格・所在地・土地/建物面積・間取り・築年・駅徒歩・種別・市区町村コード（神奈川県内）。抽出できない項目は手入力。

`--mock` はサンプルデータ（実データではない）でパイプラインの動きを見るモードです。
価格レンジと根拠（類似成約の一覧）が表示されれば成功です。

単体テスト（ネットワーク不要）:
```bash
python tests/test_logic.py
```

## 2. 実データで動かす（要キー）

不動産情報ライブラリのAPIキーを環境変数に設定します。

**Windows（PowerShell）**
```powershell
$env:REINFOLIB_KEY="（あなたのreinfolibキー）"
python run.py --price 34800000 --land 110 --building 96 --build-year 2006 --address "神奈川県小田原市南町1-1-1" --city 14206 --district 南町
```

**Mac/Linux**
```bash
export REINFOLIB_KEY="（あなたのreinfolibキー）"
python run.py --price 34800000 --land 110 --building 96 --build-year 2006 --address "神奈川県小田原市南町1-1-1" --city 14206 --district 南町
```

- `--city` は市区町村コード（小田原市=14206）。取引取得のキーです。
- `--district` は町名（例 南町）。同一町名の成約を最優先します。
- `--station-walk 12` 最寄駅の徒歩分（立地スコアに使用）。
- `--income 8000000 --down 8000000` 年収・頭金（資金スコア＝返済負担率に使用）。
- `--loan-rate 0.0125 --loan-years 35` 金利・返済期間（既定 1.25%/35年）。
- `--k 6` 価格算出に使う最類似件数、`--max-year-gap 25` 築年の離れすぎ除外、`--show 8` 根拠表示件数。
- `--years 2024,2023,2022` で対象年を変更可（既定は直近3年）。
- `GOOGLE_KEY` を設定するとジオコーディングにGoogleを使用（無ければ国土地理院GSI＝キー不要）。
- `--annual-rate 0.02` で時点補正（年率2%の例）。既定0=補正なし（透明性優先）。

フル指定の実行例：
```
python run.py --price 35000000 --land 120 --building 95 --build-year 2010 \
  --address "神奈川県小田原市城山1-2-3" --city 14206 --district 城山 \
  --station-walk 12 --income 8000000 --down 8000000
```

> 市区町村コードが分からない場合：reinfolibの XIT002（市区町村一覧）で取得できます。神奈川県内の主な例＝横須賀14201/平塚14203/鎌倉14204/藤沢14205/小田原14206/茅ヶ崎14207。

## 3. 入力（対象物件）について

MVPは**手入力前提**です（第3章：入口非依存の第一歩）。売出価格・面積・築年などを引数で渡します。
ウェブ画面では、物件ページや販売図面から**コピーした文章を貼り付ける**ことでこの入力を埋めます。PDFのアップロードは行いません（図面の作りが会社ごとに違いすぎるうえ、スキャン画像のPDFには文字が入っていないため）。

必須：`--address` `--price`。
価格評価の精度のため推奨：`--land` `--building` `--build-year` `--city` `--district`。

## 5. 制約・次フェーズ

- XIT001の取引には緯度経度が無いため、位置は「市区町村＋町名」で近似（Phase Bで確認した実データの制約）。
- 新築戸建は近隣の中古成約を基準にするため、推定幅は広めに解釈してください。
- 次：Phase D（ハザード・用途地域・人口の付与）、Phase F（100点スコア）、Buyer Profile＋ローン、最終診断、UI。

## 6. 環境変数

無い機能は表に出ない作りにしてある。設定し忘れて中途半端な画面が出るより、
出ないほうが安全という判断。

| 変数 | 無いとどうなるか |
|---|---|
| `DATABASE_URL` | 会員機能そのものが出ない（診断は動く） |
| `SECRET_KEY` | ログインのセッションが保てない |
| `RESEND_API_KEY` | ログインのメールが飛ばない |
| `CANONICAL_HOST` | 別ホストからのアクセスを本番へ寄せない |
| `OPERATOR_NAME` / `OPERATOR_ADDRESS` / `OPERATOR_TEL` | 特商法の表記が出せないので、課金の画面も出ない |
| `CONTACT_EMAIL` | 同上 |

### 課金（Stripe）

次の4つが揃って初めて申込画面が出る。1つでも欠けると `/plan` は
「試験公開中」の表示のまま。判定は `billing_on()`。

| 変数 | 値 |
|---|---|
| `BILLING_ENABLED` | `1` |
| `STRIPE_SECRET_KEY` | `sk_test_...` / 本番は `sk_live_...` |
| `STRIPE_PRICE_ID` | `price_...`（**`prod_` ではない**） |
| `STRIPE_WEBHOOK_SECRET` | `whsec_...` |

`STRIPE_WEBHOOK_SECRET` は `billing_on()` の判定には入っていないが、
無いとWebhookが400で弾かれ、支払っても**プランが上がらない**。実質必須。

**テストと本番で値が変わる。** 価格IDもWebhookシークレットも、Stripeの
テスト環境と本番環境で別物なので、本番へ移すときは作り直して差し替える。

課金が有効になると `/pro/*` はPRO会員だけになり、「試験公開中・無料」の
案内は消え、サイトマップからPROのツールURLが外れる。

※ APIキーはコードに書かず環境変数で。`.env` はコミットしないでください。
